# 方法說明與實作規格（MODELS）

> 這份文件有兩個用途：
> 1. 網站「方法說明」的來源：每個數字怎麼來、有什麼假設和限制。
> 2. 實作規格：網頁程式（`src/`）和獨立驗證程式（`tools/golden.py`）都依這份文件實作，兩邊算出來的結果必須一致（見第 4 節）。
>
> 改規則時要同時改：這份文件、`src/core/types.ts`、`src/core/constants.ts`、實作與測試。
>
> 標記：**【事實】** 由資料直接計數；**【模型】** 依模型假設計算；**【假設】** 我們選擇的解讀方式。

## 1. 共通定義

### 1.1 時間

- 所有日期都是台灣時間（Asia/Taipei，UTC+8，1979 年後沒有日光節約）。
- **日序**：`localDay(unix) = floor((unix + 28800) / 86400)`。`'YYYY-MM-DD'` 與日序互換時，用 UTC 曆法計算（`src/core/time.ts`）。
- **資料期間**：`[startDay, endDay)`，startDay = 1995-01-01、endDay = 2026-01-01（不含），共 11,323 天。
  年數 `Y = (endDay − startDay) / 365.25`（約 31.0007 年）。期間由 `meta.period.startUnix`、`endUnix` 決定，不要寫死。

### 1.2 資料

| 檔案 | 內容 | 來源 |
|---|---|---|
| `catalog.json` | ML ≥ 4.0 的地震（10,062 筆），東經 118–124 度、北緯 20–27 度 | 中央氣象署 地震目錄（E-A0073） |
| `catalog.json` 的 `near` | 每個地震到 60 公里內各縣市的距離（在縣市內為 0，四捨五入到 0.1 公里） | 內政部 縣市界線，由 `tools/build_data.py` 預先計算 |
| `felt.json` | 有感地震與全台最大震度（16,499 筆） | 中央氣象署 有感地震報告彙整 |
| `map.json` | 簡化過的縣市界，只用來畫圖 | 內政部 縣市界線（經 taiwan-atlas） |

為什麼最低只到 ML 4.0：完備規模隨年代變動（1990 年代約 2.25），4.0 以上在整個期間都相對完整。預言的門檻低於 4.0 時以 4.0 計算，**實際命中率只會更高**。

### 1.3 預言（Claim）

一則預言由四個部分組成：

| 部分 | 內容 |
|---|---|
| 發布日 `issuedAt` | 預言是哪一天說的（預設今天） |
| 時間窗 `time` | `[start, end]`，含頭尾，長度 `T = end − start + 1` 天 |
| 地區 `region` | 見 1.4 |
| 大小 `size` | 見 1.5 |

### 1.4 地區【假設】

| 類型 | 地震「在範圍內」的條件 |
|---|---|
| `taiwan`（台灣及近海） | `21 ≤ lat ≤ 26` 且 `119 ≤ lon ≤ 123`（含邊界），與試算、B3 基準模型相同 |
| `counties`（縣市 + 外推距離 b） | 對選定的任一縣市，`near` 索引裡有這個地震、而且距離 `km ≤ b`。b 為 0–60 公里；b = 0 代表只算縣市內（含其離島） |

縣市的 id 是內政部縣市代碼（`meta.counties.items` 的 `id`）。`near.county` 存的是 `meta.counties.items` 的**索引**，比對時要先把 id 換成索引。

`regionMask(region)`：長度等於 catalog 筆數的 0／1 陣列，第 i 個為 1 代表地震 i 在範圍內（地圖畫點也用它）。

### 1.5 大小【假設】

| 類型 | 有效門檻與條件 |
|---|---|
| `magnitude`（規模，中央氣象署 ML） | 嚴格 `strict`：門檻 = 值。寬鬆 `lenient`：門檻 = 值 − 0.5（沿用每日報告：只寫「M7」時，6.5 也算中）。**有效門檻** `m* = max(4.0, 門檻)`；條件 `ML ≥ m*` |
| `intensity`（震度） | 全台任一地點最大震度 `≥ 值`。值 ∈ {1, 2, 3, 4, 5, 5.5, 6, 6.5, 7}（5.5 = 5 強、6.5 = 6 強）。**地區設定不適用**（資料只有全台最大震度） |
| `unspecified`（沒說多大） | 不計算單一機率，改看解讀光譜（M4a） |

浮點數比較：`ML ≥ m*` 直接比較（資料是一位小數，門檻也是 0.5 的倍數）。

### 1.6 符合條件的地震

- 規模型：`catalog` 中 `ml ≥ m*` 且在地區內的地震。
- 震度型：`felt` 中 `intensity ≥ 值` 的地震。
- `nEvents` = 符合條件的**地震筆數**；`days` = 這些地震的日序（排序、去重）。

### 1.7 窗口命中【事實】

窗口長度 `T = min(time.days, endDay − startDay)`。

對每個起點 `d ∈ [startDay, endDay − T]`（共 `N = endDay − startDay − T + 1` 個）：

```
h(d) = 1  若存在符合條件的地震日 e，使 d ≤ e < d + T
h(d) = 0  否則
```

意思是：把過去每一天都當成「預言發布後窗口的第一天」，看那個窗口裡有沒有發生。

## 2. 解析規則（自由文字 → Claim）【假設】

解析器只做「把常見說法對應到明確的數值」，**不猜測**：解讀一律顯示在確認卡上，使用者可以改。

### 2.1 前處理

- 逐字轉換、**長度不變**（span 才能對回原文）：全形英數符號 U+FF01–U+FF5E → 半形；全形空白 → 半形空白；比對時「台」視同「臺」。
- 中文數字：〇零一二兩三四五六七八九十百，例如「十五」= 15、「三十」= 30、「一百」= 100；「六點五」= 6.5；「半」只用在「半年」。

### 2.2 時間

發布日 `d0`、星期 `w0`（0 = 週一 … 6 = 週日）。

| 說法 | kind | 窗口 |
|---|---|---|
| 今天、今日、今晚、今夜 | `today` | `[d0, d0]` |
| 明天、明日、明晚 | `tomorrow` | `[d0+1, d0+1]` |
| 後天 | `dayAfterTomorrow` | `[d0+2, d0+2]` |
| 大後天 | `date` | `[d0+3, d0+3]` |
| 這週、本週、這禮拜、這星期（周＝週） | `thisWeek` | `[d0, d0 + 6 − w0]` |
| 下週、下禮拜、下星期、下個禮拜、下個星期 | `nextWeek` | `[d0 + 7 − w0, d0 + 13 − w0]`（下週一到週日） |
| 週末、這週末 | `weekend` | `w0 ≤ 5`：`[d0 + 5 − w0, d0 + 6 − w0]`；週日：`[d0, d0]` |
| 這個月、本月、這月、月底前 | `thisMonth` | `[d0, 當月最後一天]` |
| 下個月、下月 | `nextMonth` | 下個月 1 日到最後一天 |
| 「12 月」「十二月」（後面沒有日、號） | `month` | 該月 1 日到最後一天；若該月已過，取明年；若就是本月，從 `d0` 開始 |
| 今年、今年內、年內、年底前、今年底 | `thisYear` | `[d0, 當年 12/31]` |
| N 天內、N 日內、N 天之內、未來 N 天、接下來 N 天 | `withinDays` | `[d0, d0 + N − 1]`（含今天共 N 天） |
| N 週內、N 個禮拜內、N 個星期內 | `withinDays` | 7N 天 |
| N 個月內 | `withinDays` | 30N 天 |
| 半年內 | `withinDays` | 182 天 |
| N 年內、一年內 | `withinDays` | 365N 天 |
| 這幾天、這兩天、近日 | `withinDays` | 7 天，加旗標 `time-vague` |
| 近期、最近、不久、不久後、即將、很快、隨時 | `vague` | `[d0, d0 + 29]`（30 天），加旗標 `time-vague` |
| 「11/15」「11月15日」「11月15號」「2026/11/15」 | `date` | 當天 |
| 「11/15 前」「之前」「以前」 | `untilDate` | `[d0, 該日]`（含該日） |
| 「11/10 到 11/15」（到、至、~、～、-） | `dateRange` | `[第一個日期, 第二個日期]` |
| 都沒有 | `unspecified` | `[d0, d0 + 29]`，加旗標 `time-unspecified` |

- 沒寫年份的日期：取 `d0` 當年；若早於 `d0`，改取明年。寫了年份而早於 `d0`：保留，加旗標 `time-past`。
- 有多個時間說法時，取原文中**最先出現**的。
- 天數超過 3,650 天時截斷，加旗標 `time-clamped`。

### 2.3 地點

依序在原文中比對（每個位置先試**最長**的詞，比對到的字不再重複使用）：分區別名、縣市合稱、縣市別名、「新竹」「嘉義」、台灣的說法、國外地名（詞表見 `src/core/regions.ts`）。

| 比對結果 | Claim |
|---|---|
| 有縣市、合稱或分區 | `counties`：全部縣市的聯集（依首次出現排序、去重）。外推距離預設 30 公里；原文有外海、海域、近海等字時改為 60 公里，加旗標 `region-offshore`。只比對到一個分區而沒有其他縣市時，記下 `group` |
| 只有台灣的說法 | `taiwan` |
| 都沒有 | `taiwan`，加旗標 `region-unspecified` |

- 「新竹」「嘉義」沒寫縣或市時，縣與市都算，加旗標 `region-ambiguous`。
- 比對到國外地名時加旗標 `region-out-of-scope`（detail 為地名，以「、」連接）。v1 只算台灣；若原文沒有任何台灣地名，地區用 `taiwan`，**不再**加 `region-unspecified`。
- 排除常見誤判：「其中部分」裡的「中部」不算地名。

### 2.4 大小

| 說法 | Claim |
|---|---|
| 規模 v、芮氏 v、芮氏規模 v、M v、ML v、Mw v（可接「級」） | `magnitude`，值 v（1.0–9.9，取一位小數） |
| 震度 v、v 級震度、震度 v 弱／強（可接「級」） | `intensity`，v ∈ 0–7；只有 5、6 可接弱／強（5 弱 = 5、5 強 = 5.5、6 弱 = 6、6 強 = 6.5） |
| 「v 級地震」，前後都沒有規模、芮氏、震度 | `magnitude`（寬鬆），加旗標 `size-level-ambiguous`（台灣的「級」多指震度，中國大陸媒體多指規模） |
| 有感、會搖、會晃、感覺得到 | `intensity`，值 1 |
| 大地震、強震、強烈地震、巨震、超大地震、大規模地震、大震、毀滅性、災難性、地牛翻身 | `unspecified`，加旗標 `size-unspecified`（detail 為原文用詞） |
| 都沒有 | `unspecified`，加旗標 `size-unspecified`（detail 為空字串） |

- 規模的判定方式：數值後 4 個字內有「以上、起跳、+、↑、≥」，或數值前有「至少、超過、大於」→ `strict`；其餘（包括「左右、上下、約、將近」或什麼都沒寫）→ `lenient`。
- 震度一律是「≥ 值」。
- 有明確數值時，數值優先於「大地震」「有感」等詞。多個數值時取最先出現的。
- 有效門檻低於 4.0 時加旗標 `size-below-min`。

### 2.5 其他旗標

原文有「又說、再次、再度、每週都、每天都、一直說、每次都、重複」→ 旗標 `repeat-mentioned`（提示看 M8 亂槍打鳥）。

### 2.6 Span

每個被採用的說法記錄它在**原文**中的位置 `[start, end)`（UTF-16 索引）；以上、左右、外海等修飾語記為 `modifier`。

## 3. 各模式

v1 有 8 個模式：M1、M2、M4（a、b、c）、M8、M10、M12、M13、M14。

### 總覽主數字

| 情況 | 主數字 | `headline.source` |
|---|---|---|
| 大小沒說 | 不給單一數字，給範圍 `[光譜最小 p, 光譜最大 p]` | `spectrum` |
| 期間內有符合條件的地震（`nEvents > 0`） | M1 的 `p̂` | `empirical` |
| 期間內從沒發生過 | M2 的 95% 上限（n = 0 時 μ_U = −ln 0.025 ≈ 3.689） | `poisson-upper` |

M8、M10、M12、M13 都使用主數字（大小沒說時這些模式、M1、M2、M14 都為 `null`，灌水成分為空陣列）。

計算時的旗標 `Results.flags`（依此順序、不重複）：有效門檻被夾到 4.0 時加 `size-below-min`；震度型且地區不是 `taiwan` 時加 `size-intensity-region-ignored`。

窗口長度一律用 `T = max(1, min(time.days, endDay − startDay))`。

### M1 歷史回放【事實】

**問題**：過去 31 年，同樣長度的窗口有幾成真的發生？

```
p̂ = Σ h(d) / N
```

**不確定性：年區塊拔靴法**（窗口彼此重疊，不能直接用二項分布）：

1. 每個起點 d 歸到它所在的西元年。統計每年的 `hits_y = Σ h(d)`、`windows_y`（只保留 `windows_y > 0` 的年份，依年份排序，共 K 年）。
2. 亂數產生器 mulberry32，種子 `20261104`（附錄 A），每次呼叫 M1 都重新設定種子。
3. 重複 B = 1000 次：抽 K 次 `i = floor(rng() × K)`（可重複），`p*_b = Σ hits_i / Σ windows_i`。
4. 由小到大排序，95% 區間 = `[p*[floor(0.025·B)], p*[ceil(0.975·B) − 1]]` = `[p*[25], p*[974]]`（0 起算）。

**日曆熱圖** `slots`：從 startDay 起每 T 天一格（不重疊），第 s 格 = `h(startDay + s·T)`，直到 `startDay + (s+1)·T > endDay` 為止。

### M2 固定速率（Poisson）【模型】

**問題**：如果地震以平均速率、彼此獨立地發生，機率是多少？

```
n = nEvents，λ = n / Y（每年），p = 1 − exp(−λ · T / 365.25)
```

**95% 區間**（Garwood 精確區間），X ~ Poisson(μ)：

- 下限 μ_L：n = 0 時為 0；否則解 `P(X ≥ n | μ) = 0.025`，即 `F(n − 1; μ) = 0.975`。
- 上限 μ_U：解 `F(n; μ) = 0.025`。
- 用二分法：區間 `[0, n + 10·√(n+1) + 10]`，做到區間寬度 < 1e−12 × max(1, 上界) 或 200 次。
- `F(k; μ)` 在對數空間累加（附錄 B）。λ 區間 = μ / Y，再代入 p。

**和 M1 的差別**：地震成群發生，一週裡常常一次來好幾個，所以「至少一次」的週數比固定速率模型少，短窗口時 M2 通常高於 M1。

### M4a 解讀光譜【事實】

**問題**：「大地震」到底多大？不同解讀的命中率差多少？

固定 11 種解讀（`src/core/constants.ts` 的 `SPECTRUM`）：震度 ≥ 1（有感）、≥ 3、≥ 4、≥ 5、≥ 6（全台，不套地區），以及 ML ≥ 4.5、5.0、5.5、6.0、6.5、7.0（嚴格判定，套用預言的地區）。

每項都用 M1 的 `p̂`（同一個 T）。依 p 由大到小排序，同值保持原順序。

### M4b 敏感度矩陣【事實】

規模 {4.0, 4.5, 5.0, 5.5, 6.0, 6.5, 7.0}（嚴格）× 窗口 {1, 3, 7, 14, 30, 90, 365} 天，地區用預言的地區，值為 M1 的 `p̂`。

`claimCell`：預言是規模型、有效門檻 m* 與 T 都在清單內時，為 `[i, j]`；否則 `null`。

### M4c 灌水成分【事實】

**問題**：這則預言靠哪一招讓自己容易中？

每次只把一個維度收緊，重算 M1 的 `p̂`，得到 `to`；`from` 是原預言的 `p̂`：

| 維度 | 適用條件 | 收緊後 |
|---|---|---|
| `time` | T > 1 | 只說某一天：`time = { kind: 'date', start, end: start, days: 1 }` |
| `region` | `taiwan`（規模型） | 22 個縣市各自加外推 30 公里，取命中率最高的那一個（同值取 `meta.counties.items` 中較前者）：`{ kind: 'counties', ids: [該縣市], bufferKm: 30 }` |
| `region` | `counties`，2 個以上縣市 | 取成員中命中率最高的單一縣市（同值取 `ids` 中較前者；外推距離不變；不帶 `group`） |
| `region` | `counties`，單一縣市、外推 > 0 | 外推改為 0（只算縣內） |
| `size` | 規模型 | 值 + 1.0（判定方式不變），值 + 1.0 > 9 時不適用 |
| `size` | 震度型 | 值 + 1，超過 7 時不適用 |
| `tolerance` | 規模型、寬鬆 | 改為嚴格 |

- 震度型不做 `region`（地區不適用）。大小沒說時不做灌水成分（看光譜）。
- 只保留 `to < from` 的項目。`ratio = from / to`；`to = 0` 時 `ratio = null`（收緊後期間內從沒發生過）。
- 排序：`ratio` 由大到小，`null` 視為最大；同值依 time、region、size、tolerance 順序。

### M8 亂槍打鳥【事實＋模型】

**問題**：同一個人一直發同樣的預言，至少中一次的機率？

- `p` = 總覽主數字。L = endDay − startDay。
- 比較的次數：`{1, 4, 12, 52}` 中 `n·T ≤ L` 者，再加上「一年份」`n_year = max(1, floor(365 / T))`（若 `n_year·T ≤ L`），排序去重。
- 假設各次獨立【模型】：`1 − (1 − p)^n`，期望命中次數 `n·p`。
- 歷史實際【事實】：對每個起點 `d ∈ [startDay, endDay − n·T]`，`k(d) = Σ_{j=0}^{n−1} h(d + j·T)`（連續、不重疊的 n 個窗口）。至少中一次的比例 = `k(d) ≥ 1` 的比例；平均命中次數 = `k(d)` 的平均。
- 一年份分布 `yearRun`（n = n_year；若 `n_year·T > L` 則 n = floor(L / T)）：二項分布 `C(n,k) p^k (1−p)^{n−k}`（對數空間計算）vs. 歷史上 `k(d) = k` 的比例，k = 0…n。

### M10 要連中幾次才可信【模型】

**問題**：他猜中了，該多相信他真的會預測？

參數預設：先驗 π = 0.01、目標 τ = 0.95、真有能力的人每次命中的機率 s = 1.0。p0 = 主數字。

```
猜中一次後：π1 = π·s / (π·s + (1 − π)·p0)
連中 k 次、沒有失誤：logit(π_k) = ln(π / (1 − π)) + k · ln(s / p0)
```

- 所需次數 `hitsNeeded`：π ≥ τ → 0；p0 = 0 → 1；s ≤ p0 → `null`（再怎麼連中都無法和亂猜區分）；否則 `ceil(x − 1e−9)`，`x = ln[(τ/(1−τ)) / (π/(1−π))] / ln(s / p0)`。
- 曲線 `curve`：k = 0…K，`K = min(max((hitsNeeded ?? 0) + 2, 10), 200)`；p0 = 0 時 k ≥ 1 的後驗為 1。

範例（DESIGN.md 3.1、3.2 的 7 天值）：p0 = 94.6% → 136 次；41.2% → 9 次；5.9% → 3 次；0.4% → 2 次。

### M12 生活換算與算命師等級【假設】

- 等級：由上往下找第一個 `p ≥ 下限` 的（`LEVELS`）：≥ 0.9 你今年會遇到貴人、≥ 0.5 你最近有點煩惱、≥ 0.2 擲硬幣、≥ 0.05 有點東西、≥ 0.01 稀有、其餘 神諭。
- 類比：從 `ANALOGIES`（全部是精確機率，例如擲骰子 1/6）中，選 `|logit(p) − logit(a)|` 最小者；p 先夾在 `[1e−9, 1 − 1e−9]`；同距離取清單中較前者。

### M13 資訊量【事實】

`bits = −log2(p)`（p = 0 時為 Infinity）。擲一次硬幣猜中是 1 bit，所以「相當於連續猜中 bits 次擲硬幣」。

### M14 模型比較

並列 M1（含區間）與 M2（含區間），`diff = p_M2 − p̂_M1`，並說明兩種「隨機」的差別：

## 5. 限制

- **未去群聚**：餘震也算地震。這是刻意的：預言者「猜中」餘震也算中，這正是 M1 要呈現的。
- **完備規模**：早期東部外海的小地震可能漏記，ML 4.0 附近的機率可能略為低估【推測】。
- **震度**：只有全台最大震度，無法回答「台北會不會搖到 4 級」；2020 年起震度分級改變（5、6 級拆成弱／強）。
- **地區**：「台灣及近海」是矩形；縣市外推距離是我們選的解讀，確認卡上可以改。
- **期間固定**：1995–2025，v1 不含 2026 年的地震，也不做「今天」的即時機率（避免被當成預報）。

## 附錄 A：mulberry32

```js
function mulberry32(seed) {
  let a = seed >>> 0;
  return function next() {
    let t = (a = (a + 0x6D2B79F5) >>> 0);   // 32 位元無號加法
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
```

測試向量（種子 20261104 的前 5 個值，四捨五入到 12 位）：
`0.686575185275`、`0.025461189216`、`0.660663346294`、`0.854467261815`、`0.441696755122`

Python 實作要注意：`Math.imul` 是 32 位元有號乘法，`>>>` 是無號右移，每一步都要對 2^32 取模。
