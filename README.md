# 我也會地震預測

> 輸入一則地震預言，看看隨便亂猜有多容易中。

**網站**：<https://azazelowo.github.io/i-can-predict-quakes/>

「某某說下週會大地震」——如果下週真的發生了，他是不是很準？
這個網站用中央氣象署 31 年（1995–2025）的地震目錄算給你看：**就算完全不懂地震、隨便亂猜，這種預言有多大機率會「中」**。

就像算命師說「你今年會遇到貴人」，命中率本來就很高。

---

## 為什麼做這個

民間地震預言看起來「很準」，通常來自三個可以量化的原因：

1. **台灣地震本來就多**：1995–2025 年，台灣及近海規模 5 以上的地震平均每年約 39 次。
2. **預言寫得模糊**：沒說多大、在哪、哪幾天，任何結果都能算「中」。同一句「下週會有大地震」，依「大」的定義，亂猜命中率可以從 0.4% 到 94.6%。
3. **只有猜中的會被記得**：猜錯的沒人轉傳。

這個網站把這三件事攤開來算。它屬於實務專題「基於地球物理與多維觀測資料打造地震風險評估 APP」的預期成果「民間前兆假說的量化驗證」。

## 怎麼玩

1. **貼上一則預言**，或點一個範例。目前只支援台灣及近海（縣市、鄉鎮、東部／南部這類分區）。
2. **確認我們的理解**：時間、地點、大小都可以改。沒說清楚的地方會標出來，因為那正是預言「好中」的原因。用了中央氣象署的分級名稱（中地震、弱震、小區域有感地震…）時，會附上官方定義。
3. **看結果**：先看總覽（主數字、平均每猜幾次中 1 次、和其他說法的對照），再點開想深入的模式。

只提到國外、看不出是地震預言（或其實在講演練、保險）、說的是「不會發生」、時間地點大小都沒說、說的是已經發生的地震、或說法互相矛盾時，網站會先請你確認，不直接給數字；確認之前，這則解讀也不會寫進網址。
第一次使用要先看過並同意使用規範；頁首可以換主題（白天、黑夜、沙漠黃、叢林綠、科技藍）和版面（寬螢幕可用雙欄）。這些設定只記在你的瀏覽器裡。

| 模式 | 回答的問題 |
|---|---|
| 歷史回放 | 過去 31 年，同樣的預言有幾次真的應驗？ |
| 固定速率模型（Poisson） | 如果地震隨機、平均地發生，機率是多少？ |
| 解讀光譜與敏感度 | 換個說法（多大、多久、多遠），命中率差多少？這則預言靠哪一招變得好中？ |
| 亂槍打鳥 | 一直重複同一個預言，會中幾次？ |
| 要連中幾次才可信 | 他猜中了，該多相信他？ |
| 生活換算與算命師等級 | 這個機率像擲硬幣、擲骰子，還是「你今年會遇到貴人」？ |
| 資訊量 | 這則預言到底說了多少？ |
| 為什麼模型答案不一樣 | 兩種「隨機」的差別 |

每個數字怎麼算、有什麼假設，寫在 [docs/MODELS.md](docs/MODELS.md)。

## 這不是地震預報

這裡算的是「隨便猜也會中」的**背景機率**：任何一週都差不多，不代表這週特別危險。
地震發生的時間、地點和規模，目前都無法準確預測。官方地震資訊請見[中央氣象署地震測報中心](https://scweb.cwa.gov.tw/)。

## 隱私

全部計算都在你的瀏覽器裡完成：網站不會傳送、也不會保存你輸入的內容，沒有追蹤碼。
分享連結只記錄「時間、地點、大小」這些解讀結果，**不包含你輸入的原文**（原文裡可能有人名）。

## 資料來源與授權

| 資料 | 來源 | 授權 |
|---|---|---|
| 地震目錄（ML ≥ 4.0，1995–2025） | 交通部中央氣象署 地震目錄 | 依[中央氣象署政府網站資料開放宣告](https://www.cwa.gov.tw/V8/C/information.html)，使用時註明出處 |

| 縣市界線 | 內政部 [直轄市、縣市界線](https://data.gov.tw/dataset/7442)（經 [taiwan-atlas](https://github.com/dkaoster/taiwan-atlas) 轉換） | 政府資料開放授權條款－第 1 版 |
| 鄉鎮市區名稱（只用名稱與所屬縣市） | 內政部 [鄉鎮市區界線](https://data.gov.tw/dataset/7441)（經 taiwan-atlas 轉換，`tools/build_towns.py`） | 政府資料開放授權條款－第 1 版 |
| 專有名詞的定義 | 中央氣象署 [地震百問](https://scweb.cwa.gov.tw/zh-tw/guidance/faq/)（規模分類、有感範圍分類、規模種類、震度） | 只引用定義並附連結 |

網站使用的是 `tools/build_data.py` 產生的精簡衍生資料（`public/data/`），原始資料不放在這個 repo。

## 開發

需要 Node.js 24 與 Python 3（只用標準函式庫）。

```bash
npm install
npm run dev      # 開發伺服器
npm run check    # 型別檢查 + 測試 + 建置
```

重建資料與獨立驗證的對照答案（原始資料放在實務專題的資料夾）：

```bash
EQ_DATA_DIR=<含 E-A0073-002 與 earthquake_data 的資料夾> python tools/build_data.py
python tools/golden.py
npm test
```

### 怎麼確保數字是對的

- 計算規格只有一份：[docs/MODELS.md](docs/MODELS.md)。
- `tools/golden.py` 只依規格、不看網頁程式，用 Python 再實作一次；`tests/golden.test.ts` 比對兩邊的結果。
- 主要數字和最初的可行性試算（`tools/feasibility.py`）一致。

### 部署

push 到 `main` 後，GitHub Actions（`.github/workflows/deploy.yml`）會先跑型別檢查與測試，通過才建置並發布到 GitHub Pages。
第一次使用前，到 repo 的 **Settings → Pages → Build and deployment → Source** 選「GitHub Actions」。
